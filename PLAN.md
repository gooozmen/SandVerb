# План: SAND = Drive → Bitcrusher, схема по картинке, интерактивный граф, вкл/выкл блоков

> Статус: реализовано (DSP, ядро, параметры, GUI, README). Отличие от плана: `μ = 254·amt` вместо `1 + 254·amt`, чтобы Companding = 0 давал провод.

## Цель

1. Перестроить граф сигнала по схеме пользователя (`1793800808182_image.png`).
2. SAND: вместо износа Tape/BBD сделать биткрашер по мотивам TAL-Bitcrusher. Алгоритмы свои. Перед крашером стоит педаль Drive для подогрева.
3. Каждый блок можно включать и выключать без щелчков.
4. GUI: интерактивный граф. Нажатие на блок открывает его настройки, светодиод на блоке включает и выключает его.

## 1. Схема сигнала

```
IN ─┬───────────────────────────────────────────────────────► DRY ──┐
    │                                                                │
    └─► REVERB ─┬──────────────────────────────────────────► (Mix) ─┤
                │                                                    │
                └─► COMP1 ─┬─► FEEDBACK (≤ N кадров, модули) ─┐      ├─► OUT
                           │        ▲                         ▼      │
                           └─► SAND (DRIVE → CRUSHER) ──► COMP2 ─────┤ (Fb Out)
                                    │                     │
                                    └────── SEND ◄────────┘
                                   (возврат в FEEDBACK)
```

Как это работает:
- **SAND стоит параллельно FEEDBACK.** Крашенный звук попадает в повторы через COMP2 и SEND, но повторы через SAND заново не проходят. Поэтому каша не копится от прохода к проходу.
- **SAND вне петли.** Его усиление (Drive, полки +12 дБ) не влияет на устойчивость петли.
- **Защита петли:** не больше N ≤ 16 кадров, `loopNorm`, COMP2 + `tanh`, Send ≤ 95 %, автозакрытие на тишине (`killGain`).
- **Убираются:** прямой IN → Feedback (старый `send`) и To Verb (Feedback → Reverb).

Псевдокод на сэмпл (ядро, `SandVerbCore::process`). Все `gX` — сглаженные включатели, 0…1 за ~30 мс:
```
dry    = in
verbY  = REVERB(in)                              // кроссфейд Fat/Tape как сейчас
c1in   = gVerb·verbY + (1 − gVerb)·in            // выключенный реверб = провод для ветки COMP1
c1     = mix(COMP1(c1in), c1in, gComp1)
tap    = store.read(c, D)                        // взвешенная сумма отводов, как сейчас
s      = SAND(c1)                                // DRIVE → CRUSHER, у каждого свой gX внутри
sum    = gFb·tap + gSand·sandLevel·s
c2     = tanh(mix(COMP2(sum), sum, gComp2))
store.write(tanh(c1 + gSend·send·killGain·loopNorm·c2))
out    = (1 − mix)·dry + mix·gVerb·verbY + retOut·c2
```
- Хранилище пишется всегда, даже при выключенном FEEDBACK. Так при включении в нём уже есть звук.
- Если блок полностью выключен (`g == 0` и цель 0), он не считается, CPU экономится.
- Реверб при полном выключении очищается через `clear()`, чтобы при включении не всплыл старый хвост.

## 2. DSP

### Новые файлы
- **`Source/DspUtil.h`**: сюда переезжают `XorShift` и `Biquad` из `Sand.h`. В `Biquad` добавляется `lowShelf(fc, sr, gainDb)`.
- **`Source/Drive.h`**: педаль.
- **`Source/Crusher.h`**: биткрашер.
- **`Source/Sand.h`** переписывается. `struct Sand` = `Drive` + `Crusher`, у каждого своё сглаженное вкл/выкл (кроссфейд с проводом). API:
  - `prepare(sr, seed)`;
  - `setParams(...)` на control-rate, раз в 16 сэмплов;
  - `process(x)`.

### DRIVE (`Drive.h`)

| Параметр | Диапазон | По умолчанию |
|---|---|---|
| Type | Overdrive / Tube / Fuzz | Overdrive |
| Drive | 0…40 дБ | 12 дБ |
| Tone | 0…100 % (ФНЧ 1 → 12 кГц, лог.) | 50 % |
| Level | −24…+6 дБ | 0 дБ |

Типы:
- **Overdrive.** Усиливается только полоса выше ~720 Гц: `x + (g − 1)·HP720(x)`, это даёт горб на середине. Затем мягкий `tanh`.
- **Tube.** Широкополосное усиление, клип со смещением: `tanh(u + b) − tanh(b)`, где `b = 0.3`. Получаются чётные гармоники. После клипа DC-блокер.
- **Fuzz.** ФВЧ 100 Гц, усиление ×4 сверх Drive, почти жёсткий клип: `u / (1 + |u|⁴)^¼`.

После клипа идут Tone (ФНЧ 1 полюс) и ФВЧ 30 Гц. Затем автокомпенсация: множитель по типу и Drive, подобранный в харнессе так, чтобы RMS розового шума −18 dBFS держался в пределах ±1.5 дБ на всём диапазоне Drive. Последним идёт Level.

Оверсэмплинга нет: после педали стоит крашер, и алиасинг здесь часть звука. Если понадобится, его можно добавить позже.

### CRUSHER (`Crusher.h`)
Цепочка: компандирование (сжатие) → выборка (Rate) → квантование (Bits) → расширение → шум → полки → Mix.

| Параметр | Диапазон | По умолчанию | Как работает |
|---|---|---|---|
| Bits | 1…16, плавно | 8 | `levels = 2^(bits−1)` (float, дробные биты), `q = round(x·levels) / levels` |
| Rate | 200 Гц … 48 кГц, лог. | 11025 Гц | Выборка с дробной фазой: `ph += rate/sr`, при `ph ≥ 1` берётся новый сэмпл. При `rate ≥ sr` выборка не прореживается |
| Companding | 0…100 % | 30 % | μ-law со степенью сжатия `μ = 254·amt` до квантования (при 0 — точный провод). После квантования расширение только на долю `1 − amt/2`: тихое поднимается, в нём больше шума квантования и «искр» |
| Noise | 0…100 % | 20 % | Белый шум × огибающая `|x|` (5 мс), до −12 дБ относительно сигнала. **На тишине шума нет** |
| Low | −12…+12 дБ | 0 | Полка 200 Гц |
| High | −12…+12 дБ | 0 | Полка 4 кГц |
| Mix | 0…100 % | 100 % | dry/wet внутри крашера |

Контроль: при Bits = 16, Rate = SR и нулевых Companding / Noise / полках выход совпадает со входом с точностью до шага квантования 2⁻¹⁵.

## 3. Параметры (`PluginProcessor.h/.cpp`)

| Блок | ID | Примечание |
|---|---|---|
| FEEDBACK | `frame`, `sync`, `division`, `feel`, `frames`, `falloff`, `fbon` | без изменений |
| SEND | `send` (0…95 %, по умолчанию 60 %), `sendon` | **новый смысл**: возврат COMP2 → FEEDBACK. Заменяет `feedback` |
| REVERB | `verbtype`, `rt60`, `damping`, `mix`, `verbon` | `verbon` новый |
| COMP1 | `c1thr`, `c1ratio`, `comp1on` | `comp1on` новый |
| COMP2 | `c2thr`, `c2ratio`, `comp2on` | `comp2on` новый |
| SAND | `sandon`, `sandlevel` (0…100 %, по умолчанию 70 %) | новые |
| DRIVE | `driveon`, `drvtype`, `drive`, `tone`, `drvlevel` | новые |
| CRUSHER | `crushon`, `bits`, `rate`, `compand`, `cnoise`, `lowshelf`, `highshelf`, `cmix` | новые |
| OUT | `retout` (Fb Out) | без изменений |
| MOD | `lfo1rate`, `lfo1amt`, `lfo2rate`, `lfo2amt`, `rndrate`, `rndamt`, `envamt` | без изменений |

- **Удаляются:** `feedback`, `toverb`, `sandmode`, `age`, `drift`, `grain`, `noise`.
- **Включатели по умолчанию:** все включены. Исключения: `driveon` и `crushon`, тоже включены, но с умеренными значениями.
- **Старые пресеты:** проект не выпущен. В старых состояниях `send` загрузится как количество возврата, остальное встанет на значения по умолчанию.

## 4. Ядро (`SandVerbCore.h`)

- **`LoopParams`:** новые поля по таблице выше. `toVerb` и старые `send` / `feedback` удаляются. Включатели хранятся как float 0/1 и сглаживаются в `tick()` тем же хелпером `g`.
- **Новый граф** по псевдокоду из раздела 1.
- **Удаляются:**
  - компенсация `sandLat`;
  - `off` в `FeedbackStore::read`;
  - `verbRet` с бюджетом `0.98 − feedback`. To Verb больше нет, бюджет петли — это сам Send ≤ 0.95.
- **Без изменений:** `killGain`, модули → глубина хранилища, кроссфейды длины кадра и типа реверба.
- **Для GUI добавляются:** `uiLvl[]`, уровни на проводах для подсветки графа (огибающие ветвей: verb, c1, tap, sand, c2).

## 5. GUI

### Структура файлов
- **`Source/Widgets.h`:** сюда переезжают `Knob`, `Choice` и хелперы `makeKnob` / `addChoice` из `PluginEditor`. `SandLookAndFeel` и цвета тоже здесь.
- **`Source/FlowGraph.h/.cpp`:** `class FlowGraph : public juce::Component`.
  - Узлы: `enum Node { In, Reverb, Comp1, Feedback, Mod, Sand, Comp2, Send, Out }`. У каждого узла: прямоугольник в нормированных координатах, подпись, ID включателя (у In, Out, Mod его нет), живой текст.
  - Рёбра — список пар узлов, рисуются как ортогональные `juce::Path` со стрелками. Ребро тусклое, если выключен любой из его концов. Яркость берётся из `uiLvl`.
  - `mouseDown`:
    - попадание в светодиод → `beginChangeGesture` / `setValueNotifyingHost(!v)` / `endChangeGesture` (работает автоматизация и undo хоста);
    - иначе → выбор узла и `onSelect(node)`.
  - `mouseMove`: подсветка узла под курсором, курсор-рука.
  - Живые значения на узлах:
    - COMP1 / COMP2: подавление в дБ;
    - FEEDBACK: число кадров;
    - SAND: `8 bit · 11k`;
    - REVERB: Fat / Tape.
- **`Source/Inspector.h/.cpp`:** `class Inspector : public juce::Component`. Внутри страницы, по одной `juce::Component` на узел, видна только выбранная. Наверху страницы заголовок и кнопка вкл/выкл (`ButtonAttachment`).
  - **REVERB:** Type, Decay, Damping, Mix.
  - **COMP1 и COMP2:** Threshold, Ratio, полоска подавления.
  - **FEEDBACK:** Frame, Tempo Sync, Division, Feel, Depth, Falloff.
  - **MOD:** LFO1 Rate/Amt, LFO2 Rate/Amt, Random Rate/Amt, Env Amt.
  - **SAND:** две секции. DRIVE: вкл, Type, Drive, Tone, Level. CRUSHER: вкл, Bits, Rate, Companding, Noise, Low, High, Mix. Внизу SAND Level.
  - **SEND:** Send.
  - **IN / OUT:** Mix, Fb Out.
- **`PluginEditor`:**
  - окно 1100×720: шапка 50 px (название и readout «frame ms | depth»), граф ~330 px, инспектор остальное;
  - таймер 30 Гц: `FlowGraph::repaint`, обновление индикаторов, блокировка Frame при Sync (как сейчас);
  - выбранный узел хранится в `apvts.state` (свойство `uiNode`) и восстанавливается вместе с проектом. По умолчанию выбран SAND.
